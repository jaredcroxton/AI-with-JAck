# PerformOS - Project Constitution (gemini.md)

## Tech Stack
- **Frontend:** Next.js 14 (App Router), TypeScript, Tailwind CSS
- **Backend/DB:** Supabase (PostgreSQL, Auth, Row Level Security)
- **AI:** OpenAI API (GPT-4o)
- **Deployment:** Vercel (TBC)

---

## Behavioural Rules (Law)
1. Soft delete only (all tables include `deleted_at` timestamp, nullable)
2. No "Sarah" in any demo, persona, or seed data
3. NSE = units only, no $ sign
4. No em dashes anywhere in the codebase or content
5. PerformOS capitalisation: capital P, O, S
6. Spell out one to nine, numerals for 10+
7. Dates displayed as DD Month YYYY
8. Risk flags use amber (#F59E0B for caution) and soft red (#DC2626 for high risk), never aggressive bright red (#FF0000)
9. Executive dashboard shows aggregated data only, never individual team member responses
10. Two clear entry points on home screen (Manager / Team Member), no setup wizards
11. App must feel safe and trustworthy given sensitive human data

## Data Schema

### users
```json
{
  "id": "uuid (PK, from Supabase Auth)",
  "email": "string (unique, not null)",
  "full_name": "string (not null)",
  "role": "enum: manager | team_member | executive",
  "manager_id": "uuid (FK -> users.id, nullable, for team_members)",
  "avatar_url": "string (nullable)",
  "created_at": "timestamp",
  "updated_at": "timestamp",
  "deleted_at": "timestamp (nullable, soft delete)"
}
```

### sessions
```json
{
  "id": "uuid (PK)",
  "manager_id": "uuid (FK -> users.id, not null)",
  "team_member_id": "uuid (FK -> users.id, not null)",
  "scheduled_at": "timestamp (not null)",
  "status": "enum: scheduled | in_progress | completed | cancelled",
  "manager_notes": "text (nullable)",
  "ai_summary": "text (nullable, generated by OpenAI)",
  "ai_coaching_prompt": "text (nullable, generated by OpenAI)",
  "mood_rating": "integer 1-5 (nullable, from team member)",
  "created_at": "timestamp",
  "updated_at": "timestamp",
  "deleted_at": "timestamp (nullable, soft delete)"
}
```

### reflections
Pre-meeting reflections submitted by team members before a session.
```json
{
  "id": "uuid (PK)",
  "session_id": "uuid (FK -> sessions.id, not null)",
  "team_member_id": "uuid (FK -> users.id, not null)",
  "wins": "text (nullable)",
  "challenges": "text (nullable)",
  "support_needed": "text (nullable)",
  "overall_feeling": "enum: great | good | okay | struggling | critical",
  "submitted_at": "timestamp (nullable)",
  "created_at": "timestamp",
  "updated_at": "timestamp",
  "deleted_at": "timestamp (nullable, soft delete)"
}
```

### action_items
```json
{
  "id": "uuid (PK)",
  "session_id": "uuid (FK -> sessions.id, not null)",
  "assigned_to": "uuid (FK -> users.id, not null)",
  "created_by": "uuid (FK -> users.id, not null)",
  "title": "string (not null)",
  "description": "text (nullable)",
  "due_date": "date (nullable)",
  "status": "enum: open | in_progress | completed",
  "created_at": "timestamp",
  "updated_at": "timestamp",
  "deleted_at": "timestamp (nullable, soft delete)"
}
```

### risk_flags
```json
{
  "id": "uuid (PK)",
  "team_member_id": "uuid (FK -> users.id, not null)",
  "session_id": "uuid (FK -> sessions.id, nullable)",
  "flag_type": "enum: disengagement | burnout | conflict | psychological_safety | flight_risk",
  "severity": "enum: caution | high_risk",
  "evidence": "text (not null, AI-generated rationale)",
  "detected_at": "timestamp (not null)",
  "resolved_at": "timestamp (nullable)",
  "resolved_by": "uuid (FK -> users.id, nullable)",
  "created_at": "timestamp",
  "updated_at": "timestamp",
  "deleted_at": "timestamp (nullable, soft delete)"
}
```

### team_health_scores
Aggregated scores for executive dashboard. No individual data exposed.
```json
{
  "id": "uuid (PK)",
  "manager_id": "uuid (FK -> users.id, not null)",
  "period_start": "date (not null)",
  "period_end": "date (not null)",
  "avg_mood": "decimal (1.0-5.0)",
  "session_completion_rate": "decimal (0.0-1.0)",
  "open_action_items_count": "integer",
  "active_risk_flags_count": "integer",
  "team_size": "integer",
  "created_at": "timestamp",
  "updated_at": "timestamp"
}
```

## Architectural Invariants
1. All database access goes through Supabase client with Row Level Security enforced
2. AI calls (OpenAI) are server-side only, never from the client
3. Executive view queries only the team_health_scores table, never sessions/reflections/risk_flags directly
4. Every table with user data has soft delete (deleted_at column)
5. Auth roles are enforced at both RLS and application level
